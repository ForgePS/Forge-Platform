# Pattern — Approve & Reject Workflow

**Last Updated:** 2026-07-30 · **Author:** FX Program

## Purpose

Shared approval/rejection transitions with who/when/why/audit/notification.

## Scope

Needs Review → Approved / Rejected (and product extensions).

## Goals

Identical approve/reject UX across products; reason when required.

## Examples

Approve inspection; reject permit with reason.

## Anti-patterns

Product-specific approval modals with different semantics for “Approved”.

## Dependencies

Workflow · Notifications · Timeline.
