# FX-S0 — Program Charter

**Program:** Forge Experience (FX)  
**Version:** FX-S0  
**Status:** APPROVED

## Purpose

Create the complete shared experience foundation for every Forge product so the Forge ecosystem feels like one platform, not a collection of separate applications.

## Products covered

- Forge RMS
- Forge Academy
- Forge Industrial Safety
- Future Forge applications

## What Forge Experience is

Forge Experience is **not** another application.

Forge Experience is the shared platform standard that defines how every Forge product:

- Looks
- Behaves
- Feels

## Mission

Design Forge Experience as the single source of truth for:

| Domain | Ownership |
| --- | --- |
| User experience | FX |
| Design standards | FX |
| Navigation | FX |
| Components | FX |
| Dashboards | FX |
| Workspaces | FX |
| Accessibility | FX |
| Mobile experience | FX |
| Workflow standards | FX |
| Record standards | FX |
| Reporting standards | FX |
| Forms standards | FX |
| Notifications | FX |
| Search | FX |
| User interaction | FX |
| Branding | FX |

Every Forge product shall inherit these standards.

## Goals

1. Create one ecosystem.
2. Users instantly understand any Forge product without retraining.
3. Moving from RMS to Academy feels identical.
4. Moving from Academy to Industrial feels identical.
5. Only business logic changes between products — never user experience.

## Non-goals

Forge Experience does **not** own:

- Business rules
- Database design
- Cloud infrastructure
- Authentication
- Permissions
- Tenant logic
- Backend APIs
- Industry regulations
- Operational policies
- Product-specific workflows

Those remain inside each product.

## Success criteria (FX-S0)

- Charter, vision, boundaries, and philosophy are documented and approved
- Documentation tree exists under `docs/forge-experience/`
- Products are instructed to extend FX rather than replace or duplicate it
- Subsequent FX sprints can deepen tokens, components, shell, and frameworks without redefining ownership

## Authority

FX standards are binding for product UX. Product teams extend FX; they do not fork parallel design systems.
