# FX Reporting Framework

**Program:** Forge Experience (FX)  
**Version:** FX-S0  
**Status:** APPROVED (Part 3)

Every Forge report shares common behavior.  
Reports are analytical lenses on records and operational data — not a second application metaphor.

## Ownership

| Layer                                                                 | Owner                  |
| --------------------------------------------------------------------- | ---------------------- |
| Report chrome, filters UX, export entry points, print layout patterns | **FX**                 |
| Queries, regulatory definitions, data sources, scheduling backends    | **Product / platform** |

---

## Report types

| Type                | Role                            |
| ------------------- | ------------------------------- |
| Table Reports       | Tabular operational/analytical  |
| Summary Reports     | Aggregated summaries            |
| Executive Reports   | Leadership posture              |
| Operational Reports | Shift / queue / readiness       |
| Compliance Reports  | Compliance evidence             |
| Trend Reports       | Over-time analysis              |
| Exception Reports   | Outliers / failures             |
| Scheduled Reports   | Time-delivered                  |
| Ad Hoc Reports      | User-composed within guardrails |
| Printable Reports   | Print-optimized layout          |

## Exports

Reports support export to:

- PDF
- Excel
- CSV
- JSON
- API (machine access when entitled)

Export actions are permission-gated and audited.

## Report capabilities

Filters · Grouping · Sorting · Saved templates · Scheduled delivery · Bookmarks · Charts · Maps · Drill down · Role permissions · Tenant restrictions

Drill-down targets **records** via the workspace framework when applicable.

## Report metadata (every report)

Every report includes:

| Metadata         | Role                      |
| ---------------- | ------------------------- |
| Generated By     | Actor                     |
| Generated Date   | Timestamp                 |
| Filters Applied  | Transparent criteria      |
| Data Source      | Declared source           |
| Version          | Report definition version |
| Audit Identifier | Traceable run id          |

## Accessibility

- Tables use proper headers
- Charts critical to decisions need text/table alternatives
- Export unavailable states explained

## Anti-patterns

- Product-unique report viewers with different filter metaphors
- Hidden filters not shown in metadata
- Drill-down to unauthorized rows
- Spreadsheet editing as the default report UX
