# DEF-S8-023 — Clean malware verdict does not automatically trigger format detection

**ID:** DEF-S8-023  
**Severity:** P1  
**Status:** CLOSED  
**Date:** 2026-07-30  
**Affected service:** `worker-service` (IAM) + malware→detect queue handoff  
**Deployment:** Worker IAM SendMessage grant + worker TD `:26` (log wrap). Verified on patch baseline `import-s8-patch-20260730113557`.

## Summary

After a CLEAN malware verdict the job is updated to `SCANNING` / `currentStage=FORMAT_DETECTION`, but `import.upload.detect.v1` is never successfully published. Operators observed stuck jobs until a **manual** SQS detect replay. Malware scan messages for the same jobs accumulate in the imports DLQ.

## Reproduction

1. Authenticated operator uploads a clean synthetic CSV on development.
2. Complete upload → malware worker scans → file `malwareVerdict=CLEAN`, `malwareGatePassedAt` set.
3. Observe job remains `SCANNING` / `FORMAT_DETECTION` indefinitely.
4. Imports primary queue drains; detect never advances to `READY_FOR_MAPPING`.
5. Manual `SendMessage` of `import.upload.detect.v1` → job advances to `READY_FOR_MAPPING`.
6. Imports DLQ contains `IMPORT_MALWARE_SCAN` bodies for the stuck job (receive count ≥ maxReceiveCount).

## Expected state transition

```text
UPLOADED → SCANNING (malware) → CLEAN persisted → FORMAT_DETECTION_QUEUED
→ format detect worker → READY_FOR_MAPPING
```

Automatic; no operator SQS replay.

## Actual state transition (pre-fix)

```text
UPLOADED → SCANNING → CLEAN persisted + currentStage=FORMAT_DETECTION
→ enqueueFormatDetect AccessDenied
→ malware message retry → DLQ
→ job stuck until manual detect replay
```

## Root cause

**Missing `sqs:SendMessage` on the worker task role for `forge-*-sqs-imports`.**

| Principal        | Imports queue Receive/Delete         | Imports queue SendMessage         |
| ---------------- | ------------------------------------ | --------------------------------- |
| API task role    | (not consumer)                       | **Allowed** (`grantSendMessages`) |
| Worker task role | **Allowed** (`grantConsumeMessages`) | **Missing**                       |

Code path (`import-malware-processor.ts`):

1. Transaction commits CLEAN verdict + `currentStage=FORMAT_DETECTION`.
2. `enqueueFormatDetect()` calls `SQS SendMessage` with `import.upload.detect.v1`.
3. IAM denies SendMessage → exception.
4. Outer `catch` returns `"retry"`.
5. Consumer does not delete the malware message; after `maxReceiveCount` it lands in DLQ.
6. Format detection never runs.

Not caused by: clean verdict enum mismatch, detect processor logic (manual replay proves detect works), tenant context, or API upload completion.

## Required regression tests

- Unit/processor: CLEAN path attempts format-detect enqueue (mocked SQS).
- Live: upload→complete→automatic `READY_FOR_MAPPING` **without** manual detect replay.
- IAM: worker role policy includes `sqs:SendMessage` on imports queue ARN.
