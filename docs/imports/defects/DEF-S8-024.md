# DEF-S8-024 — Incorrect default neutral execution adapter in deployed API

**ID:** DEF-S8-024  
**Severity:** P1  
**Status:** CLOSED  
**Date:** 2026-07-30  
**Affected service:** `platform-api`  
**Deployment:** API task definition `:42` (`import-s8-patch-20260730113557`)

## Summary

`POST /api/v1/imports/jobs/:id/execute` without an explicit `adapterKey` derived a product-shaped key (`FORGE_RMS:CORE:personnel@1`). The worker registry only registers the neutral `reference:generic:record@1` until S9 adapters are authorized. Execute therefore failed with `IMPORT_ADAPTER_MISSING` / `NON_RETRIABLE_JOB`.

## Reproduction

1. Control-plane or upload job reaches `APPROVED` with staged rows.
2. Executor calls execute **without** `adapterKey`.
3. Job goes `QUEUED` then `FAILED` with `IMPORT_ADAPTER_MISSING`.

## Expected behavior

Default adapter resolves to `reference:generic:record@1` when no product adapter is registered / no explicit key is provided.

## Actual behavior (API `:40`)

Default used `adapterRegistryKey({ productKey, moduleKey, recordType })` → unregistered product key.

## Root cause

Pre-S9 execute path assumed product adapter keys exist. S8 forbids product adapters; only the reference adapter is registered in the worker.

## Fix (source)

`apps/platform-api/src/modules/imports/import-execution.service.ts`:

```ts
const adapterKey = input.adapterKey ?? "reference:generic:record@1";
```

## Required regression tests

- Execute without `adapterKey` completes against reference adapter on development after deploy.
- Explicit `adapterKey` still honored when provided.
